Biwenger · ¿A quién fichar hoy?

Investigación de mercado y recomendador de fichajes para una liga fantasy a partir de la API de Biwenger
Autor: Gonzalo Velasco Toronjo
Repositorio: github.com/guensovt/biwenger-fichajes
Fecha: octubre de 2026
Entregables: analisis_biwenger.ipynb, biwenger_datos.py y este documento

1. Objetivo

En una liga de Biwenger (fantasy de LaLiga) hay cientos de jugadores: los del mercado diario y los de las plantillas de los rivales, que se pueden fichar pagando su cláusula cuando no está bloqueada. Revisarlos uno a uno cada día no es práctico.

El proyecto se conecta a la API de Biwenger, descarga cada día el estado real de la liga y responde a una pregunta concreta: ¿qué jugadores me conviene fichar hoy? Solo se proponen dos tipos de oportunidad:

  • Deportiva: jugadores que puntuarían más que el peor de mi plantilla en su posición.
  • Económica: jugadores cuyo valor de mercado sube con fuerza cada día (comprar y revender con beneficio).

El resultado es una lista corta y explicada, en lugar de cientos de filas.

2. Fuente de datos: la API de Biwenger

Biwenger no publica una API oficial, pero su web consume una API REST en JSON. Se ha tomado como referencia el proyecto comunitario pablopb3/biwenger-api y se han verificado los endpoints inspeccionando las peticiones de la web con las herramientas de desarrollador del navegador.

EndpointAutenticaciónDatos que aporta
/api/v2/accountSíMis ligas, mi manager, competición, sistema de puntos y bloqueo para ejecutar cláusulas
/api/v2/marketSíJugadores en venta (liga y otros managers) y mi saldo
/api/v2/leagueSíClasificación (managers) y reglas de cláusulas de la liga
/api/v2/user/{id}SíPlantilla de cada manager, cláusulas y fechas de bloqueo
cf.biwenger.com/.../competitions/{c}/dataNoCatálogo: precio, variación diaria, puntos en casa/fuera, posiciones, estado
cf.biwenger.com/.../teams/{c}/{id}NoCalendario de cada equipo con la dificultad de cada partido

Las peticiones privadas requieren la cabecera Authorization: Bearer … de una sesión iniciada en la web. Cada ejecución hace unas 35 consultas, secuenciales y con pausas de 1 segundo.

3. Arquitectura: un proceso ETL

1 · ExtracciónSesión cifrada → consultas HTTPS con curl → captura fechada en capturas/FECHA_UTC/
➜
2 · TransformaciónValidación, unión por ID, cláusulas y bloqueos en hora de Madrid, variación €/día
➜
3 · ModeloPuntos esperados en los 3 próximos partidos y rating 0–100
➜
4 · ResultadosResumen, oportunidades, mercado de hoy y ranking completo

El código de extracción está en el módulo biwenger_datos.py. El notebook analisis_biwenger.ipynb contiene las fases 2–4 con el código técnico plegado y explicaciones desplegables, para poder seguirlo de arriba abajo.

3.1 Extracción

  • Detección automática: con la sesión se consulta /account; de ahí salen la liga, el manager, la competición y el sistema de puntos. Así el mismo código sirve para cualquier usuario.
  • Sesión protegida: el token se pide una sola vez en una entrada oculta y se guarda cifrado fuera del proyecto: DPAPI en Windows y llavero del sistema (keyring) en macOS/Linux. Nunca aparece en el código, en las salidas ni en la línea de comandos: se pasa a curl por la entrada estándar.
  • Lista de hosts permitidos: solo biwenger.as.com y cf.biwenger.com; el token solo se envía al primero y no se siguen redirecciones.
  • Robustez: los errores transitorios del servidor (404, 429, 5xx) se reintentan dos veces; si algo falla o una plantilla no cuadra con la clasificación, no se guarda una captura incompleta.
  • Trazabilidad: cada ejecución crea una carpeta nueva con los JSON y la hora de cada consulta. El modo "local" permite repetir el análisis sin conexión.

3.2 Transformación

  • Todos los datos se unen por identificador, nunca por nombre; los valores ausentes se marcan como «Sin datos», no como cero.
  • ¿Cuándo se puede clausular? Se toma la fecha más tardía de cuatro bloqueos: protección del jugador, fecha de compra + días de activación de la liga, cupo de cláusulas recibidas por el propietario y mi propio cupo de cláusulas ejecutadas. Se muestra «Ejecutable» o la fecha de desbloqueo en hora de Madrid.
  • Los jugadores con varias posiciones (por ejemplo, centrocampista/delantero) cuentan en todas ellas.

4. Modelo de recomendación

4.1 Puntos esperados

Para cada jugador se estiman los puntos de sus 3 próximos partidos a partir de su media en casa o fuera según toque, suavizada para que un jugador con un solo partido bueno no domine, y ajustada por la dificultad del rival que da la propia API (0–100):

ajuste rival = ± |media| × 0,004 × (50 − dificultad)   (máximo ±20 %)

4.2 Rating 0–100

Rating = 40 % deportivo + 50 % económico + 10 % coste
ComponenteCálculo
DeportivoPercentil de los puntos esperados frente a los jugadores de su posición
EconómicoMedia de los percentiles de la subida diaria en € y en %
CostePrecio de entrada frente al valor de mercado (pagar el valor = 50)

4.3 Selección de oportunidades

TipoCriterio (configurable)
⚽ Más puntos que mi plantilla≥ +0,5 pts/partido sobre mi peor jugador de esa posición y no baja más de 50.000 €/día
💰 Para hacer dineroSube ≥ 50.000 €/día; se calcula en cuántos días recupera el sobreprecio al ritmo actual
🛒 Mercado de hoyVeredicto para cada jugador en venta: buena compra, revisar estado, mejora pero baja de precio, no aporta
⏰ DesbloqueosOportunidades cuya cláusula se desbloquea en menos de 72 horas

Es una regla de decisión explicable, no un modelo entrenado: cada recomendación indica a quién sustituye, cuánto mejora y cuánto sube al día.

6. Instrucciones de ejecución (para cualquier usuario)

El proyecto funciona con la cuenta de quien lo ejecute: basta con su propia sesión de Biwenger. Código: github.com/guensovt/biwenger-fichajes (ver README).

6.1 Instalación

git clone https://github.com/guensovt/biwenger-fichajes.git
cd biwenger-fichajes
python -m venv .venv
.venv\Scripts\activate          # Windows
source .venv/bin/activate       # macOS / Linux
pip install -r requirements.txt

Requisitos: Python 3, VS Code con la extensión Jupyter (o Jupyter Lab) y curl, incluido en Windows 10/11, macOS y casi todos los Linux.

6.2 Obtener tu Authorization (solo la primera vez)

  1. Inicia sesión en biwenger.as.com.
  2. Pulsa F12 y ve a la pestaña Red / Network.
  3. Recarga (F5) y filtra por api.
  4. Selecciona una petición a biwenger.as.com/api/v2/… (por ejemplo account).
  5. En Request Headers, haz clic derecho sobre Authorization → Copiar valor (Bearer eyJ…).
Importante: ese valor da acceso a tu cuenta mientras la sesión esté activa. No lo compartas, no lo escribas en el código y no lo subas a GitHub.

6.3 Ejecutar

  1. Abre analisis_biwenger.ipynb, elige el kernel de .venv y pulsa Ejecutar todo.
  2. La primera vez aparece una casilla oculta: pega el Authorization. Se guarda cifrado y las siguientes ejecuciones no lo piden.
  3. Consulta los resultados en la sección 4. Resultados (enlace en el índice inicial).

7. Limitaciones y siguientes pasos

  • La API no es oficial: puede cambiar sin aviso.
  • No se conocen minutos, titularidades ni alineaciones; el estado del jugador (lesión, sanción) solo genera un aviso.
  • Los parámetros son heurísticos y no están calibrados. Como siguiente paso, se guardarán las predicciones de cada captura y se compararán con los puntos reales (error MAE frente a una media simple) para ajustar los pesos.
  • La subida diaria puede cambiar mañana: recuperar el sobreprecio «al ritmo de hoy» no está garantizado.

8. Conclusión

El proyecto aplica los contenidos del módulo a un caso real: conexión a una API autenticada, extracción robusta y segura, transformación y validación de JSON, y un análisis que convierte cientos de registros en una decisión concreta. Al detectar la liga a partir de la sesión y guardar el token cifrado, cualquier usuario de Biwenger puede usarlo con su propia cuenta.
